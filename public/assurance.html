What you are looking at

1 — A bounded list, not a score

The items above are what a person has to look at, derived from which claims the decision actually rests on. Criticality comes from reachability in the claim graph, never from volume: a claim one agent emitted once is exactly as load-bearing as one four hundred agents discussed. On the frontier demo that ships with the package, 2,287,133 records reduce to 13 items. A shorter list is not a better case — it can equally mean detection got worse, which is why that refusal is a property in the code.

2 — It says what it did not check

Every verdict carries its own coverage. NOT_ASSESSED is a first-class answer, kept apart from “we looked and found nothing” everywhere in the engine — collapsing those is how a gap comes to read as a clean bill of health.

3 — When it holds, it returns the work order

Each item arrives with what would close it, in a form the next agent run can act on rather than a human re-reading the case to work out what was missing.

Run it yourself

This page has limits so one browser tab cannot monopolise a shared process. The CLI has none — it needs no account, sends nothing anywhere, and the demo it ships with folds 2.28 million records in about three seconds. 

pip install release-gate
release-gate assure your-run.jsonl
release-gate assure your-run.jsonl --review      # the one-screen version
release-gate assure your-run.jsonl --json        # for a pipeline

Exit codes: 0 PROMOTE · 10 HOLD · 1 BLOCK — so it drops into CI without a wrapper. Full walkthrough →

What it will not tell you

Not that a release is safe. Not that a result is guaranteed correct. Not that the gate is unhackable — twenty attacks run against the engine itself and one is recorded NOT_DEFENDED with what bounds it instead. Not that hallucinations are solved, or that an expert has been replaced: the output is a list of what needs a person. Each of those refusals is a property in code that cannot return anything else.
